02 / Hardware → learning → blind proof

Run the real experiment.

A rigid S20 Ultra facing a PC monitor, with a stationary diffuser in between. The phone is manually exposed and its IP Webcam snapshots are captured by Python on the same local network. Your monitor is the training target—not a source of hidden answers during inference.

STAGE 01 / LOCK

Freeze the optics

Keep the phone, diffuser and monitor fixed. Use the saved 420-pixel geometry calibration. Lock manual focus, white balance, shutter and ISO. Avoid recursive IP-camera previews in the illuminated area.

STAGE 02 / LEARN

Collect matched pairs

Show random geometric source images, wait for the IP-camera frame to settle, and learn a 2D inverse model on the RTX 3060. Reserve unseen shapes for honest validation.

STAGE 03 / REVEAL

Test unfamiliar images

Type previously unseen letters or draw a new shape. Compare the actual camera image, reconstructed image and known screen. Score the reconstruction against a simple intensity baseline.

Windows quick start

In the already calibrated directory, update the repository and launch the new experiment. The PyTorch installation must support your GPU for CUDA acceleration; the program also supports CPU mode.

cd /d E:\DocsHouse\1065\LightScan
git pull --ff-only
python3.13 -m pip install -r requirements-xray.txt
python3.13 -c "import torch; print(torch.cuda.is_available())"

python3.13 diffuser_xray.py --url http://192.168.1.157:8080/ --calibration runs\rig_locked\calibration.json --zone-px 420 --samples 240 --settle 0.8 --output runs\diffuser_inverse_001

The default 0.8 s settle interval is deliberately longer than the initial 0.14 s suggestion: unmatched screen and camera frames can create a convincing but false inverse. For a synthetic test without the phone: python3.13 diffuser_xray.py --sim --samples 80 --epochs 8. Keep the inverse model's real-time performance and accuracy as measurements, not promises.

03 / What would count as a breakthrough?

No magic without a control.

What we already measured

The real Samsung/monitor rig achieved approximately 0.30 camera pixels geometric reprojection error across nine illuminated points, and a stable manual-exposure brightness response. The first tiny-dot shadow scan was weak; it did not perform inversion.

What remains unproven

Whether the diffuser preserves enough spatial information for reconstruction at useful resolution; whether a learned model beats direct blur and mean-image baselines; and whether previously unseen text can be recovered reliably. A camera seeing a monitor recursively is a feedback experiment, not evidence of inverse imaging.

The non-leak test

Train on shapes, never letters. Test on fresh letters typed only after training. Turn the physical diffuser to a new orientation and watch whether recovery degrades. A learned optical inverse should require recalibration when the scattering medium changes.

The hard limit

If the diffuser truly destroys spatial information at the camera's sensor resolution and noise level, no small U-Net can recreate it faithfully. The model can generate plausible guesses, but the ground-truth score will reveal the difference.
